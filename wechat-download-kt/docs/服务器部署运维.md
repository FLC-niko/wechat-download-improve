## 4. 配置说明（服务器上 `config.yaml` 要点）

```yaml
server:
  host: 0.0.0.0
  port: 8001
  site_url: http://175.178.183.71:4001
store:
  db_path: data/rss.db
rabbitmq:
  host: "localhost"                    # 生产值用 RABBITMQ_HOST 环境变量注入
  port: 5672
  username: "guest"
  password: "guest"                    # 生产环境禁止把真实密码写入文档
notification:
  wecom_webhook_url: ""
  feishu_webhook_url: ""
adapter:
  api_key: ""                          # 用 ADAPTER_API_KEY 环境变量注入
```

生产配置保持 `wx.main.enabled: false`：`ret=200013` 是主微信接口永久失效标志，不按临时频控自动恢复。当前 `adb.enabled: true`，设备监督每 15 秒通过服务器回环端口 `15037` 检查 Windows USB ADB Server；`manage.sh` 为 Java 进程注入 `ADB_SERVER_SOCKET=tcp:127.0.0.1:15037`。同时保持 `weread.auto_qr_notification_enabled: true` 与 `weread.eink.auto_qr_notification_enabled: true`，无设备或自动恢复失败时仍可回退机器人二维码。E-Ink `-2041` 属于官方人工验证，ADB 不绕过验证；服务生成限时验证链接/二维码，人工提交腾讯验证码后自动探测恢复。验证完成前任务立即熔断 E-Ink 并回退 Web/缓存，真实探测按 `weread.eink.human_verify_probe_interval`（默认 3600 秒）长退避。文章任务先检查 SQLite：已有可用文章就直接返回；空缓存只有在可信覆盖已确认时才返回 `EMPTY`，否则才消耗一次远端缺口翻页请求。

### 4.1 ADB 长期连接拓扑

```text
手机 USB
  → Windows C:\platform-tools\adb.exe（127.0.0.1:5037）
  → Windows 计划任务 TopviewAdbReverseTunnel
  → ssh -R 127.0.0.1:15037:127.0.0.1:5037
  → 服务器 127.0.0.1:15037
  → wechat-download-kt（ADB_SERVER_SOCKET=tcp:127.0.0.1:15037）
```

Windows 文件：

```text
C:\ProgramData\TopviewAdbTunnel\adb-reverse-tunnel.ps1
C:\ProgramData\TopviewAdbTunnel\id_ed25519
C:\ProgramData\TopviewAdbTunnel\adb-reverse-tunnel.log
```

约束与设计：

- 手机 Wi-Fi IP 不参与长期连接，避免校园网网段隔离和 DHCP 变化。
- 隧道密钥在服务器 `authorized_keys` 中使用 `restrict` 和 `permitlisten="127.0.0.1:15037"`，不能登录 Shell，也不能监听其他地址。
- 计划任务以 `Administrator` 登录触发，复用已经在手机上授权的 ADB RSA 身份；任务内 watchdog 在 SSH 退出后 5 秒重连。
- Windows ADB 只保留 USB 序列号 `C6P7HYDY9LYHAQON`，不要同时保留 `192.168.10.104:5555`，否则同一手机会被发现两次。
- 已验证的现场设备是 Xiaomi `22041216C`、Android 12 / API 31。API 31 走现代坐标路线；经典路线是 API `<=29` 或微信 `<8.0.40`。

检查命令：

```bash
ss -ltn | grep ':15037 '
ADB_SERVER_SOCKET=tcp:127.0.0.1:15037 adb devices -l
curl http://127.0.0.1:8001/api/adb/status
```

正常结果应为 `AUTO_RECOVERABLE`，并且只有一个 USB 序列号。`15037` 消失时先查 Windows 任务和 `adb-reverse-tunnel.log`，不要改成对校园网开放的 `0.0.0.0:5037`。

### 4.2 E-Ink `-2041` 人工验证链路

```text
E-Ink API 返回 -2041
  → 服务进入 HUMAN_VERIFY_REQUIRED 并停止高频请求
  → 企业微信 / 飞书发送文字链接与二维码
  → 管理员访问 175.178.183.71:4001/weread/eink/verify/{nonce}
  → Nginx 只转发验证相关路径到 127.0.0.1:8001
  → 浏览器完成人工腾讯验证码
  → ticket/randstr 仅在内存中用于一次恢复探测
  → 成功后 E-Ink 会话恢复；失败则返回新的验证链接
```

手工查看或重新生成当前验证入口：

```bash
curl http://127.0.0.1:8001/api/weread/eink/verify/status
curl -X POST http://127.0.0.1:8001/api/weread/eink/verify/start
```

- 验证链接默认 5 分钟有效且只能提交一次；不要把 nonce 长期记录到工单或日志。
- 验证票据和 `randstr` 不持久化、不由状态接口返回，也不应写入日志。
- 这条链路不依赖 AAOS，也不会向安卓微信读书 App 发送通知；二维码由机器人发送给管理员。
- ADB serial、手机微信读书 App 身份、服务端 E-Ink `deviceId` 相互独立。服务不会通过 ADB 读取或复用 App 私有 `deviceId`。
- 4001 的原前端与原 `/api/` 后端继续保留；仅验证相关精确路径交给 8001，禁止把整个 4001 改为本项目反代。

### 方式 C：GitHub 自动轮询部署（当前服务器使用）

服务器已配置用户级 cron：

```cron
@reboot /home/topview/projects/wechat-download-improve/wechat-download-kt/manage.sh start
* * * * * /home/topview/projects/wechat-download-improve/wechat-download-kt/github-poll-deploy.sh
```

轮询脚本每分钟检查 GitHub `main` 分支，只在提交涉及 `wechat-download-kt/` 时构建；其他 monorepo 项目不会触发本应用部署。
脚本在独立 worktree 中执行 `installDist -x test --no-daemon`，构建成功后才替换 `build/install` 并重启应用；启动脚本会等待 `/api/health` 通过。
构建失败、仓库同步失败或新版本启动失败时保留旧构建；部署过程由 `flock` 防止并发执行。

## 7. 已知事项与故障排查

1. **日志中大量 `L1/L2/L3 全部失败`（任务处理失败）**
  - L2（微信读书）当前已迁移账号 `909705585`，但 `/api/weread/status` 显示凭证已过期（`EXPIRED`）；需要重新发起微信读书扫码登录。
   - L1（appmsgpublish）默认关闭；若人工启用后出现 `200013`，应用会永久停用该通道并立即降级，不会在 60 秒后重试。

2. **`ADB 设备探查失败: Cannot run program "adb"`**
   - 先确认服务器安装了 `adb`，再确认 `manage.sh` 注入了 `ADB_SERVER_SOCKET=tcp:127.0.0.1:15037`。直接运行 `adb devices` 会连接服务器自己的默认 daemon，不能代表 Windows USB 设备链路。

3. **`config.yaml` 未随仓库分发**
  - 该文件在 `.gitignore` 中，自动部署执行 `git reset --hard` 也不会覆盖它；仍需确认 `config.yaml` 存在且端口为 `8001`。

4. **`run.sh` 在服务器上不可用**
   - 它引用了仓库未定义的任务 `buildFatJar`，请统一使用 `manage.sh` 或手动 `java -jar` / `installDist` 启动方式。

5. **微信凭证**
   - `data/.credentials.json` 和 `data/rss.db` 已从旧服务器迁移。微信公众平台凭证过期前 24h/6h 会通过企业微信/飞书机器人推送提醒；过期后需重新扫码：
     `curl -X POST http://10.21.76.61:8001/api/login/start`
   - 微信读书凭证过期后，通过应用接口重新发起登录：
     `curl -X POST http://10.21.76.61:8001/api/weread/login`

6. **ADB 扫码恢复提示「登录失败，请重新扫码登录」与离线 OCR 加速**
   - 微信客户端在扫描到已过期或已被选过的二维码时，页面会提示「登录失败，请重新扫码登录」。
   - 为避免等待 60 秒轮询超时，服务端先读取 `uiautomator` 节点文本；节点不可见时再执行纯本地 OCR。OCR 裁剪覆盖屏幕 28%~82%，避免漏掉 Android 11/12 WebView 中位置偏低的失败提示。
   - 识别后会点击左上角关闭、发送一次 BACK，并显式启动 `LauncherUI` 复位；每次恢复结束的 `finally` 还会再次执行复位。
   - 若服务器未安装 `tesseract-ocr` 和 `chi_sim`，节点识别仍可工作；两者都不可用时安全退回 60 秒超时。

## 8. ADB 改造回滚

服务器已保留启用 ADB 前的文件：

```text
/home/topview/projects/wechat-download-improve/wechat-download-kt/manage.sh.before-adb-20260924-105100
/home/topview/projects/wechat-download-improve/wechat-download-kt/config.yaml.before-adb-20260924-105100
/home/topview/.ssh/authorized_keys.before-adb-tunnel-20260924-024222
```

如需完整撤销本次 ADB 链路：

1. Windows 停止并删除 `TopviewAdbReverseTunnel` 计划任务。
2. 服务器恢复上面两份 `manage.sh` / `config.yaml` 备份并执行 `./manage.sh restart`。
3. 确认 `/api/adb/status` 回到 `MANUAL_ONLY`。
4. 仅在确认不再需要该隧道密钥时，才用 `authorized_keys` 备份恢复 SSH 授权文件。

AAOS 旧版 APK 与内部数据库备份位于服务器：

```text
/home/topview/projects/wechat-download-improve/deploy/rollback/com.topviewclub.crawling-v1.apk
/home/topview/projects/wechat-download-improve/deploy/rollback/com.topviewclub.crawling-v1-data.tar
```

由于旧版和本机新构建 APK 的 debug 证书不同，不能直接 `adb install -r`；升级前必须保留旧 APK/数据，MIUI 清装时还需要在手机上确认安装。

## 9. 快速排障速查

| 现象 | 处理 |
|---|---|
| 应用未监听 8001 | `./manage.sh log` 看启动日志；确认 `config.yaml` 中 `port: 8001` |
| 健康检查不通 | `./manage.sh status`；检查应用进程、`logs/app.log` 和 8001 端口 |
| RabbitMQ 连不上 | 查 `rabbitmqamqp.topviewclub.cn` 网络/账号；日志见 `RabbitMqService` 相关行 |
| 需要看某任务处理详情 | `grep '任务处理' logs/app.log` |
| ADB 扫码界面卡在登录失败 | 检查 `uiautomator`/OCR 日志、`chi_sim` 语言包和 `dismissAuthorizationAndReset`；不需要 `gnirehtet`，手机继续使用自身校园网 Wi-Fi |
| 部署新代码 | 自动轮询每分钟检查；手工部署时使用 `./github-poll-deploy.sh`，不要直接覆盖 `build/install` |

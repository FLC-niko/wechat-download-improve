## 5. 部署步骤（可复现）

### 方式 A：本地构建 + 同步（首次采用，速度快）

```bash
# 1. 本地构建分发包（利用本地 Gradle 缓存）
cd wechat-download-kt
./gradlew installDist -x test

# 2. 同步到服务器（仅适用于明确要发布本地构建产物的场景）
scp -r build/install topview@10.21.76.61:/home/topview/projects/wechat-download-improve/wechat-download-kt/build/
scp config.yaml topview@10.21.76.61:/home/topview/projects/wechat-download-improve/wechat-download-kt/config.yaml

# 3. 服务器上启动
ssh topview@10.21.76.61
cd ~/projects/wechat-download-improve/wechat-download-kt
./manage.sh start
```

### 方式 B：服务器本地构建（无本地缓存时依赖下载较慢）

```bash
cd ~/projects/wechat-download-improve/wechat-download-kt
./gradlew installDist -x test --no-daemon --info
# 首次需下载 Kotlin 插件与 Maven 依赖；国内网络下建议耐心等待
# 注意：仓库 build.gradle.kts 未定义 buildFatJar/shadow 任务，
# run.sh 中的 buildFatJar 不可用，请使用 installDist
```

### 启动

```bash
cd ~/projects/wechat-download-improve/wechat-download-kt
./manage.sh start        # 后台启动，日志写入 logs/app.log，PID 写入 app.pid
```

### 方式 C：GitHub 自动轮询部署（当前服务器使用）

服务器已配置用户级 cron：

```cron
@reboot /home/topview/projects/wechat-download-improve/wechat-download-kt/manage.sh start
* * * * * /home/topview/projects/wechat-download-improve/wechat-download-kt/github-poll-deploy.sh
```

轮询脚本每分钟检查 GitHub `main` 分支，只在提交涉及 `wechat-download-kt/` 时构建；其他 monorepo 项目不会触发本应用部署。
脚本在独立 worktree 中执行 `installDist -x test --no-daemon`，构建成功后才替换 `build/install` 并重启应用；启动脚本会等待 `/api/health` 通过。
构建失败、仓库同步失败或新版本启动失败时保留旧构建；部署过程由 `flock` 防止并发执行。

自动部署相关文件：

```text
wechat-download-kt/github-poll-deploy.sh             # GitHub 轮询和部署
wechat-download-kt/manage.sh                         # 启停管理
~/.local/state/wechat-download-kt/deploy.log         # 部署日志
~/.local/state/wechat-download-kt/cron.log           # cron 输出
~/.local/state/wechat-download-kt/deploy.lock        # 部署锁
```

查看或修改当前用户的 cron：

```bash
crontab -l
crontab -e
```

## 7. 已知事项与故障排查

1. **日志中大量 `L1/L2/L3 全部失败`（任务处理失败）**
  - L2（微信读书）当前已迁移账号 `909705585`，但 `/api/weread/status` 显示凭证已过期（`EXPIRED`）；需要重新发起微信读书扫码登录。
   - L1（appmsgpublish 主通道）频控：微信接口被限频后有 60s 降级期，正常现象。

2. **`ADB 设备探查失败: Cannot run program "adb"`**
   - 服务器未安装 `adb`。若需要微信读书设备自动恢复功能，需 `apt install adb`（需管理员）并接入 ADB 设备；否则仅影响 weread 恢复通道，不影响主链路。

3. **`config.yaml` 未随仓库分发**
  - 该文件在 `.gitignore` 中，自动部署执行 `git reset --hard` 也不会覆盖它；仍需确认 `config.yaml` 存在且端口为 `8001`。

4. **`run.sh` 在服务器上不可用**
   - 它引用了仓库未定义的任务 `buildFatJar`，请统一使用 `manage.sh` 或手动 `java -jar` / `installDist` 启动方式。

5. **微信凭证**
   - `data/.credentials.json` 和 `data/rss.db` 已从旧服务器迁移。微信公众平台凭证过期前 24h/6h 会通过企业微信/飞书机器人推送提醒；过期后需重新扫码：
     `curl -X POST http://10.21.76.61:8001/api/login/start`
   - 微信读书凭证过期后，通过应用接口重新发起登录：
     `curl -X POST http://10.21.76.61:8001/api/weread/login`

## 8. 快速排障速查

| 现象 | 处理 |
|---|---|
| 应用未监听 8001 | `./manage.sh log` 看启动日志；确认 `config.yaml` 中 `port: 8001` |
| 健康检查不通 | `./manage.sh status`；检查应用进程、`logs/app.log` 和 8001 端口 |
| RabbitMQ 连不上 | 查 `rabbitmqamqp.topviewclub.cn` 网络/账号；日志见 `RabbitMqService` 相关行 |
| 需要看某任务处理详情 | `grep '任务处理' logs/app.log` |
| 部署新代码 | 自动轮询每分钟检查；手工部署时使用 `./github-poll-deploy.sh`，不要直接覆盖 `build/install` |

# 2026-10-18 静默期恢复、Web 扫码入库策略与"依次点击"题型

## 1. E-Ink 自动解题：静默期不再阻断恢复

**问题**：`notifyHumanVerification` 在提醒静默期（默认 10800s）直接 return，
自动解题也被一并跳过。一次解题失败后，账号在静默期内不会再尝试恢复，
只能等应用重启（内存态清空）或静默期结束。

**修复**（`WeReadEinkRuntime.kt`）：
- 静默只抑制提醒消息，自动解题照常执行；
- 新增 `autoRecoveryInFlight` 防重入，并发的 -2041 事件只跑一个恢复流程；
- 提醒名额仍用 CAS 抢占，恢复成功时按既有逻辑重置静默计时。

**配套**（`solver-daemon.mjs`）：轮内预算守卫（pick/confirm/verify 前检查剩余
预算）与 CDP 命令 30s 超时，保证在 App 300s 超时前返回结果，避免
`SIDE_CAR_UNAVAILABLE` 误报。

线上验证（10-18 全天）：日志中自动恢复成功 144 次、失败 29 次；
多数恢复为 `attempts=1`，单次 15~20s。

## 2. Web 渠道扫码：按实际扫码账号入库（无 ADB 手工路径）

**问题**：无 ADB（手机未开机）时人工只能用手上的微信扫码，实际登录账号是
909705585；而 Web 目标账号是 938161607（手机端微信）。旧逻辑"账号不一致即拒绝"，
导致扫码成功但凭证被丢弃，通知还显示"等待扫码超时"。

**修复**（`WeReadWebAuth.kt`）：
- 扫码返回的账号与目标不一致时，**按实际扫码账号入库**（账号池天然支持多账号），
  不覆盖目标账号凭证；发送 `weread_account_recovered`（含 expected_vid）；
- 目标账号（938161607）记录一次失败退避，避免手机未开机期间反复推送二维码；
- 二维码刷新页按钮 303 跳转（Main.kt），脚本/API 调用仍返回 JSON。

**线上验证**：21:57 扫码 → 日志 `按实际账号入库: expected=938161607, actual=909705585`
→ 909 入池 ACTIVE → `/api/ready` web=true、collection_ready=true，
"没有可用的微信读书账号"告警归零；938 进入 BACKOFF。

**约定**：无 ADB 时手扫 = 909705585；手机启动 ADB 后由设备恢复 938161607。

### 2.1 Web 侧 -2041 转交浏览器自动验证

-2041 是**账号级**风控（Web 采集也会触发，扫码登录不能解除）。此前 Web 侧只
`markHumanVerificationRequired` 熔断，没有任何恢复入口。

- `WeReadWebClient` 页面 -2041、`CredentialHealthChecker` Web 探测 -2041 都会调用
  `WeReadEinkRuntime.requestHumanVerificationRecovery(vid, reason)`，复用同一套
  浏览器解题 + ticket 完成流程；
- `checkWebAccounts` 现在也遍历 `HUMAN_VERIFY_REQUIRED` 账号，每轮（5 分钟）
  转交恢复请求；
- 自动验证尝试新增冷却：同一封禁期间按 `human_verify_probe_interval`（默认 3600s）
  限频，避免 Web 健康检查把解题器打成连续轰炸；恢复成功后冷却清零；
- 验证通过后 `noteHumanVerifyRecovery` 会 `clearHumanVerificationRequired`，
  把 Web 账号池状态恢复为 ACTIVE，等待下一次探测确认。

## 3. "依次点击"图标序列题型

题面："依次点击："+ 噪点 sprite（黑色剪影序列）+ 彩色描边图标主图（672×480）。

实现（`ops/eink-browser-solver/seq_match.py`，`POST 127.0.0.1:9993/seq-pick`）：

1. sprite 剪影：12 分位亮度 + 低饱和阈值提取，bbox 邻近合并碎片；
2. 主图搜索图：饱和度 98 分位（彩色描边）+ 暗色高对比（黑描边），闭运算后填洞；
3. 多尺度（0.8–2.2）× 多角度（-40°…40°）二值模板匹配，
   分数 = 0.55·TM_CCOEFF_NORMED + 0.28·recall + 0.17·precision；
4. 全局非重叠组合（DFS），按 sprite 从左到右顺序输出点击点；
5. 门控：`min_score < SOLVER_SEQ_MIN_SCORE`（默认 0.62）→ 点"换一组"；
   seq 轮数 > `SOLVER_SEQ_MAX_ROUNDS`（默认 3）→ 快速失败。

参考实现：[adnogpu/TXCaptcha](https://github.com/adnogpu/TXCaptcha)（同款 fixture）。

离线验收：11 个历史样本 + 10:39 批新样本（2–5 个图标）人工检查，
高分样本落点正确，低分样本会被门控拦下；线上效果以 verify errorCode 回归
（`DEBUG_DIR/seq-attempts.jsonl` + 带时间戳样本留档）。

## 4. 运维备注

- `wereadEinkHealthCheckInterval=300s`，但 E-Ink 探测受
  `RealtimeTaskActivity.isBackgroundWorkAllowed()`（无任务且静默 120s）约束，
  持续有实时任务时健康探测会推迟；实际恢复仍由实时请求触发的 -2041 驱动。
- 服务器 /opt/eink-browser-solver 不在自动部署范围，改动需手工 scp 并
  `systemctl restart eink-clip-service eink-browser-solver`。
